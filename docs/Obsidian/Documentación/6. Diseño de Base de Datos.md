## 6.1 Introducción

### Propósito

Este documento describe el diseño completo de la base de datos del sistema HELIOS. Incluye el modelo entidad-relación, la definición de cada tabla con sus campos y restricciones, las políticas de seguridad RLS, los índices de rendimiento y el script SQL completo listo para ejecutar en Supabase.

### Motor de base de datos

|Característica|Detalle|
|---|---|
|Motor|PostgreSQL 15|
|Proveedor|Supabase|
|Plan|Free tier (500MB)|
|Región|us-east-1 (más cercana a Panamá)|
|Cifrado en reposo|AES-256 (gestionado por Supabase)|
|Cifrado en tránsito|TLS 1.2+|

### Convenciones

|Convención|Descripción|
|---|---|
|`id`|UUID generado automáticamente con `gen_random_uuid()`|
|`created_at`|Timestamp automático con `now()`|
|`updated_at`|Timestamp actualizado manualmente en cada UPDATE|
|FK|Clave foránea siempre referencia al `id` de la tabla padre|
|Enums|Implementados como `text` con `CHECK` constraint|
|Soft delete|No aplica — se usa campo `estado` o `activo`|

## 6.3 Definición de Tablas

### Tabla: `sedes`

**Descripción:** Policlínicas y centros de salud de la red HELIOS a nivel nacional.

|Campo|Tipo|Restricción|Descripción|
|---|---|---|---|
|`id`|`uuid`|PK, NOT NULL, DEFAULT gen_random_uuid()|Identificador único|
|`nombre`|`text`|NOT NULL|Nombre oficial de la sede|
|`provincia`|`text`|NOT NULL, CHECK (lista)|Provincia panameña|
|`direccion`|`text`||Dirección física|
|`telefono`|`text`||Teléfono con formato +507|
|`correo`|`text`||Correo institucional @helios.gob.pa|
|`horario`|`text`||Descripción del horario de atención|
|`activa`|`boolean`|NOT NULL, DEFAULT true|Si la sede está operativa|
|`created_at`|`timestamp`|DEFAULT now()|Fecha de creación|

**Valores permitidos para `provincia`:** Panamá · Panamá Oeste · Colón · Chiriquí · Veraguas · Coclé · Herrera · Los Santos · Darién · Bocas del Toro · Guna Yala

---

### Tabla: `pacientes`

**Descripción:** Ciudadanos registrados en el sistema HELIOS como usuarios pacientes.

| Campo                | Tipo        | Restricción                              | Descripción                 |
| -------------------- | ----------- | ---------------------------------------- | --------------------------- |
| `id`                 | `uuid`      | PK, NOT NULL, DEFAULT gen_random_uuid()  | Identificador único         |
| `user_id`            | `uuid`      | FK → auth.users(id), UNIQUE              | Referencia a cuenta de Auth |
| `nombre`             | `text`      | NOT NULL                                 | Nombre completo             |
| `cedula`             | `text`      | NOT NULL, UNIQUE                         | Cédula panameña o pasaporte |
| `correo`             | `text`      | NOT NULL, UNIQUE                         | Correo electrónico          |
| `telefono`           | `text`      |                                          | Teléfono +507               |
| `fecha_nacimiento`   | `date`      |                                          | Fecha de nacimiento         |
| `sexo`               | `text`      | CHECK (masculino, femenino, no_indicado) | Sexo del paciente           |
| `canal_notificacion` | `text`      | CHECK (app, correo, sms), DEFAULT correo | Canal preferido             |
| `tipo_cobertura`     | `text`      | CHECK (css, minsa), DEFAULT minsa        | Tipo de seguro              |
| `created_at`         | `timestamp` | DEFAULT now()                            | Fecha de registro           |

---

### Tabla: `medicos`

**Descripción:** Profesionales de salud registrados y autorizados en el sistema.

|Campo|Tipo|Restricción|Descripción|
|---|---|---|---|
|`id`|`uuid`|PK, NOT NULL, DEFAULT gen_random_uuid()|Identificador único|
|`user_id`|`uuid`|FK → auth.users(id), UNIQUE|Referencia a cuenta de Auth|
|`sede_id`|`uuid`|FK → sedes(id), NOT NULL|Sede principal del médico|
|`nombre`|`text`|NOT NULL|Nombre completo con título|
|`especialidad`|`text`|NOT NULL, CHECK (lista)|Especialidad médica|
|`disponible`|`boolean`|NOT NULL, DEFAULT true|Si está activo en el sistema|
|`created_at`|`timestamp`|DEFAULT now()|Fecha de registro|

**Valores permitidos para `especialidad`:** medicina_general · pediatria · cardiologia · dermatologia · ginecologia · odontologia · ortopedia · neurologia · oftalmologia · psiquiatria

---

### Tabla: `disponibilidad`

**Descripción:** Horarios de atención configurados por cada médico para cada día de la semana.

|Campo|Tipo|Restricción|Descripción|
|---|---|---|---|
|`id`|`uuid`|PK, NOT NULL, DEFAULT gen_random_uuid()|Identificador único|
|`medico_id`|`uuid`|FK → medicos(id), NOT NULL|Médico al que pertenece|
|`dia_semana`|`int`|NOT NULL, CHECK (0-6)|0=Domingo, 1=Lunes... 6=Sábado|
|`hora_inicio`|`time`|NOT NULL|Hora de inicio de atención|
|`hora_fin`|`time`|NOT NULL|Hora de fin de atención|
|`activo`|`boolean`|NOT NULL, DEFAULT true|Si ese bloque está activo|

---

### Tabla: `citas`

**Descripción:** Citas médicas registradas en el sistema. Es la tabla central del sistema HELIOS.

|Campo|Tipo|Restricción|Descripción|
|---|---|---|---|
|`id`|`uuid`|PK, NOT NULL, DEFAULT gen_random_uuid()|Identificador único|
|`paciente_id`|`uuid`|FK → pacientes(id), NOT NULL|Paciente que agenda|
|`medico_id`|`uuid`|FK → medicos(id), NOT NULL|Médico asignado|
|`sede_id`|`uuid`|FK → sedes(id), NOT NULL|Sede de la cita|
|`fecha_hora`|`timestamp`|NOT NULL|Fecha y hora de la cita|
|`estado`|`text`|NOT NULL, CHECK (lista), DEFAULT confirmada|Estado actual|
|`motivo_cancelacion`|`text`||Motivo si fue cancelada|
|`confirmacion_asistencia`|`boolean`|DEFAULT false|Si el paciente confirmó|
|`confirmado_at`|`timestamp`||Cuándo confirmó asistencia|
|`codigo_cita`|`text`|UNIQUE, NOT NULL|Código legible (HEL-2026-XXXXX)|
|`created_at`|`timestamp`|DEFAULT now()|Fecha de creación|
|`updated_at`|`timestamp`|DEFAULT now()|Última modificación|

**Valores permitidos para `estado`:** confirmada · cancelada · reprogramada · completada · en_espera

**Motivos de cancelación permitidos:** emergencia · no_puede_asistir · cambio_medico · error_agendamiento · otro

---

### Tabla: `notificaciones`

**Descripción:** Registro de todas las notificaciones enviadas o pendientes a pacientes.

| Campo         | Tipo        | Restricción                                | Descripción            |
| ------------- | ----------- | ------------------------------------------ | ---------------------- |
| `id`          | `uuid`      | PK, NOT NULL, DEFAULT gen_random_uuid()    | Identificador único    |
| `cita_id`     | `uuid`      | FK → citas(id), NOT NULL                   | Cita relacionada       |
| `paciente_id` | `uuid`      | FK → pacientes(id), NOT NULL               | Destinatario           |
| `tipo`        | `text`      | NOT NULL, CHECK (lista)                    | Tipo de notificación   |
| `canal`       | `text`      | NOT NULL, CHECK (correo, sms)              | Canal de envío         |
| `estado`      | `text`      | NOT NULL, CHECK (lista), DEFAULT pendiente | Estado del envío       |
| `leida`       | `boolean`   | NOT NULL, DEFAULT false                    | Si fue leída en la app |
| `enviado_at`  | `timestamp` |                                            | Cuándo fue enviada     |
| `created_at`  | `timestamp` | DEFAULT now()                              | Fecha de creación      |

**Valores permitidos para `tipo`:** recordatorio_24h · recordatorio_1h · confirmacion · cancelacion · cambio · resultado_disponible

**Valores permitidos para `estado`:** pendiente · enviado · fallido · leido

---

### Tabla: `sync_logs`

**Descripción:** Registro de auditoría de todas las operaciones de sincronización entre sedes. No contiene datos personales de pacientes.

|Campo|Tipo|Restricción|Descripción|
|---|---|---|---|
|`id`|`uuid`|PK, NOT NULL, DEFAULT gen_random_uuid()|Identificador único|
|`sede_origen_id`|`uuid`|FK → sedes(id)|Sede donde ocurrió el evento|
|`sede_destino_id`|`uuid`|FK → sedes(id)|Sede receptora del cambio|
|`tabla`|`text`|NOT NULL|Tabla afectada (ej: citas)|
|`operacion`|`text`|NOT NULL, CHECK (insert, update, delete)|Tipo de operación|
|`registro_id`|`uuid`|NOT NULL|ID del registro sincronizado|
|`estado`|`text`|NOT NULL, CHECK (lista), DEFAULT exitoso|Resultado|
|`intentos`|`int`|NOT NULL, DEFAULT 1|Número de intentos realizados|
|`error_mensaje`|`text`||Mensaje de error si falló|
|`created_at`|`timestamp`|DEFAULT now()|Fecha del evento|

**Valores permitidos para `estado`:** exitoso · fallido · reintentando

> ⚠️ **Regla de seguridad RR-08:** Esta tabla NUNCA debe contener cédula, correo, nombre ni ningún dato personal del paciente. Solo IDs y metadatos de la operación.

## 6.4 Script SQL Completo

Ejecutar en Supabase → SQL Editor en un solo bloque:

```sql
-- ============================================
-- HELIOS — Script de Base de Datos v1.0
-- Universidad Tecnológica de Panamá
-- Calidad de Software — Mayo 2026
-- ============================================

-- EXTENSIONES
create extension if not exists "pgcrypto";

-- ============================================
-- TABLA: sedes
-- ============================================
create table sedes (
  id uuid primary key default gen_random_uuid(),
  nombre text not null,
  provincia text not null check (provincia in (
    'Panama', 'Panama Oeste', 'Colon', 'Chiriqui',
    'Veraguas', 'Cocle', 'Herrera', 'Los Santos',
    'Darien', 'Bocas del Toro', 'Guna Yala'
  )),
  direccion text,
  telefono text,
  correo text,
  horario text,
  activa boolean not null default true,
  created_at timestamp default now()
);

-- ============================================
-- TABLA: pacientes
-- ============================================
create table pacientes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) unique,
  nombre text not null,
  cedula text not null unique,
  correo text not null unique,
  telefono text,
  fecha_nacimiento date,
  sexo text check (sexo in ('masculino', 'femenino', 'no_indicado')),
  canal_notificacion text check (
    canal_notificacion in ('app', 'correo', 'sms')
  ) default 'correo',
  tipo_cobertura text check (
    tipo_cobertura in ('css', 'minsa', 'privado', 'particular')
  ) default 'minsa',
  created_at timestamp default now()
);

-- ============================================
-- TABLA: medicos
-- ============================================
create table medicos (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) unique,
  sede_id uuid references sedes(id) not null,
  nombre text not null,
  especialidad text not null check (especialidad in (
    'medicina_general', 'pediatria', 'cardiologia',
    'dermatologia', 'ginecologia', 'odontologia',
    'ortopedia', 'neurologia', 'oftalmologia', 'psiquiatria'
  )),
  disponible boolean not null default true,
  created_at timestamp default now()
);

-- ============================================
-- TABLA: disponibilidad
-- ============================================
create table disponibilidad (
  id uuid primary key default gen_random_uuid(),
  medico_id uuid references medicos(id) not null,
  dia_semana int not null check (dia_semana between 0 and 6),
  hora_inicio time not null,
  hora_fin time not null,
  activo boolean not null default true,
  constraint disponibilidad_horario_check
    check (hora_fin > hora_inicio)
);

-- ============================================
-- TABLA: citas
-- ============================================
create table citas (
  id uuid primary key default gen_random_uuid(),
  paciente_id uuid references pacientes(id) not null,
  medico_id uuid references medicos(id) not null,
  sede_id uuid references sedes(id) not null,
  fecha_hora timestamp not null,
  estado text not null check (estado in (
    'confirmada', 'cancelada', 'reprogramada',
    'completada', 'en_espera'
  )) default 'confirmada',
  motivo_cancelacion text check (motivo_cancelacion in (
    'emergencia', 'no_puede_asistir', 'cambio_medico',
    'error_agendamiento', 'otro'
  )),
  confirmacion_asistencia boolean default false,
  confirmado_at timestamp,
  codigo_cita text unique not null
    default 'HEL-' || to_char(now(), 'YYYY') || '-'
    || lpad(floor(random() * 99999)::text, 5, '0'),
  created_at timestamp default now(),
  updated_at timestamp default now(),
  -- RR-11: Un médico no puede tener dos citas al mismo tiempo
  constraint citas_medico_fecha_unique
    unique (medico_id, fecha_hora)
);

-- ============================================
-- TABLA: notificaciones
-- ============================================
create table notificaciones (
  id uuid primary key default gen_random_uuid(),
  cita_id uuid references citas(id) not null,
  paciente_id uuid references pacientes(id) not null,
  tipo text not null check (tipo in (
    'recordatorio_24h', 'recordatorio_1h', 'confirmacion',
    'cancelacion', 'cambio', 'resultado_disponible'
  )),
  canal text not null check (canal in ('app', 'correo', 'sms')),
  estado text not null check (
    estado in ('pendiente', 'enviado', 'fallido', 'leido')
  ) default 'pendiente',
  leida boolean not null default false,
  enviado_at timestamp,
  created_at timestamp default now(),
  -- RR-07: No enviar el mismo recordatorio dos veces
  constraint notif_cita_tipo_unique
    unique (cita_id, tipo, canal)
);

-- ============================================
-- TABLA: sync_logs
-- ============================================
create table sync_logs (
  id uuid primary key default gen_random_uuid(),
  sede_origen_id uuid references sedes(id),
  sede_destino_id uuid references sedes(id),
  tabla text not null,
  operacion text not null check (
    operacion in ('insert', 'update', 'delete')
  ),
  registro_id uuid not null,
  estado text not null check (
    estado in ('exitoso', 'fallido', 'reintentando')
  ) default 'exitoso',
  intentos int not null default 1,
  error_mensaje text,
  created_at timestamp default now()
  -- NOTA: Esta tabla nunca almacena datos personales
  -- Solo IDs y metadatos de operaciones (RR-08)
);
```

## 6.5 Políticas RLS (Row Level Security)

```sql
-- ============================================
-- HABILITAR RLS EN TODAS LAS TABLAS
-- ============================================
alter table sedes enable row level security;
alter table pacientes enable row level security;
alter table medicos enable row level security;
alter table disponibilidad enable row level security;
alter table citas enable row level security;
alter table notificaciones enable row level security;
alter table sync_logs enable row level security;

-- ============================================
-- POLÍTICAS: sedes (pública para lectura)
-- ============================================
create policy "sedes_lectura_publica"
on sedes for select
using (activa = true);

-- ============================================
-- POLÍTICAS: medicos (pública para lectura)
-- ============================================
create policy "medicos_lectura_publica"
on medicos for select
using (disponible = true);

-- ============================================
-- POLÍTICAS: disponibilidad (pública para lectura)
-- ============================================
create policy "disponibilidad_lectura_publica"
on disponibilidad for select
using (activo = true);

-- ============================================
-- POLÍTICAS: pacientes
-- ============================================
-- Paciente ve solo sus propios datos
create policy "paciente_ver_su_perfil"
on pacientes for select
using (auth.uid() = user_id);

-- Paciente puede actualizar su propio perfil
create policy "paciente_actualizar_perfil"
on pacientes for update
using (auth.uid() = user_id);

-- ============================================
-- POLÍTICAS: citas
-- ============================================
-- Paciente ve solo sus citas
create policy "paciente_ver_sus_citas"
on citas for select
using (
  auth.uid() = (
    select user_id from pacientes where id = paciente_id
  )
);

-- Paciente puede crear citas
create policy "paciente_crear_cita"
on citas for insert
with check (
  auth.uid() = (
    select user_id from pacientes where id = paciente_id
  )
);

-- Paciente puede actualizar sus citas (cancelar/reprogramar)
create policy "paciente_actualizar_cita"
on citas for update
using (
  auth.uid() = (
    select user_id from pacientes where id = paciente_id
  )
  and estado = 'confirmada'
);

-- Médico ve sus propias citas
create policy "medico_ver_sus_citas"
on citas for select
using (
  auth.uid() = (
    select user_id from medicos where id = medico_id
  )
);

-- ============================================
-- POLÍTICAS: notificaciones
-- ============================================
-- Paciente ve solo sus notificaciones
create policy "paciente_ver_sus_notificaciones"
on notificaciones for select
using (
  auth.uid() = (
    select user_id from pacientes where id = paciente_id
  )
);

-- Paciente puede actualizar (marcar como leída)
create policy "paciente_leer_notificacion"
on notificaciones for update
using (
  auth.uid() = (
    select user_id from pacientes where id = paciente_id
  )
);

-- Sistema puede insertar notificaciones (Edge Functions)
create policy "sistema_insertar_notificacion"
on notificaciones for insert
with check (true); -- Controlado por service_role en Edge Functions

-- ============================================
-- POLÍTICAS: sync_logs (solo administradores)
-- ============================================
-- Solo service_role puede ver sync_logs
-- Los administradores acceden via service_role key
-- No hay política pública para sync_logs

-- Sistema puede insertar logs
create policy "sistema_insertar_sync_log"
on sync_logs for insert
with check (true);
```

## 6.6 Índices de Rendimiento

```sql
-- Búsqueda de citas por paciente (Mis Citas)
create index idx_citas_paciente
on citas (paciente_id, fecha_hora desc);

-- Búsqueda de citas por médico (Agenda del médico)
create index idx_citas_medico
on citas (medico_id, fecha_hora asc);

-- Búsqueda de citas por fecha (Recordatorios automáticos)
create index idx_citas_fecha
on citas (fecha_hora)
where estado = 'confirmada';

-- Búsqueda de médicos por sede y especialidad
create index idx_medicos_sede_especialidad
on medicos (sede_id, especialidad)
where disponible = true;

-- Búsqueda de notificaciones por cita y tipo (evitar duplicados)
create index idx_notif_cita_tipo
on notificaciones (cita_id, tipo);

-- Búsqueda de sync_logs por estado (Dashboard admin)
create index idx_sync_estado
on sync_logs (estado, created_at desc);

-- Búsqueda de disponibilidad por médico y día
create index idx_disponibilidad_medico_dia
on disponibilidad (medico_id, dia_semana)
where activo = true;
```

## 6.11 Reglas de Negocio en la Base de Datos

|Regla|Implementación en BD|
|---|---|
|RR-02: No dos citas mismo médico mismo día mismo paciente|No implementado en BD, validar en servicio|
|RR-03: No mostrar horarios ocupados|Consulta que excluye `fecha_hora` con `estado = confirmada`|
|RR-07: No duplicar recordatorio|Constraint UNIQUE en `(cita_id, tipo, canal)`|
|RR-08: Sin datos personales en sync_logs|No hay FK a pacientes ni campos de datos personales|
|RR-11: No dos citas mismo médico mismo horario|Constraint UNIQUE en `(medico_id, fecha_hora)`|
|RR-12: Motivo obligatorio en cancelación|Validar en servicio, no en BD (campo opcional por diseño)|
